# 条件模块：适用性判断与内容归属

生成与审稿均须读取本文件（CN-58）。15 章主目录保持稳定；下表是检查全集，最终 PRD 只展开适用内容。同一行为只定义一次，其他位置引用稳定条目编号。

## 判定方法

- **适用**：已确认的范围或素材存在触发特征。具体规则不全时仍标适用，将缺口登记 Q-n；不能用“不适用”掩盖缺失。
- **不适用**：已确认的责任边界可以说明不涉及该模块。给出具体理由，不能只写“传统需求”“素材未提及”。上游负责某能力时仍须检查本文的消费和失败责任。
- **待确认**：触发特征本身未知，且可能影响本文承诺。在正文保留必要问题和建议口径并登记 Q-n；无需为每个未知模块展开整套空表。

来源与事实按 CN-20 至 CN-27 处理。AI 自行判断适用性，不为每个模块追加审批；只有影响范围、权限、预算或验收责任的业务取舍交给决策方。任务边界、失败处理、质量判据和评测方式是 AI 需求的基础检查；其他模块按实际特征触发。

## 模块目录

模块 ID 是生成报告中的稳定标识，不是 PRD 需求编号。报告须逐项填写下表全部模块，不把模块目录复制到业务 PRD。

| 模块 ID | 模块 | 触发特征 | 最少需要回答 | 内容归属 |
|---|---|---|---|---|
| CFG | 可配置能力 | 业务、运营或管理员可改变产品行为 | 谁能改、可选范围与默认行为、生效范围与时机、存量影响、审核和审计是否需要 | 功能需求与规则；参数定义引用契约。未暴露给用户的调优参数留在技术设计或 ADR |
| INPUT | 输入与内容形态 | 格式、语言、长度、结构或质量差异会影响处理结果 | 支持等级、各形态可观察行为、失败处置、验证方法 | 功能需求、异常与功能验收；需要统计质量时再关联效果验收 |
| META | 元数据传递 | 跨环节消费或传递来源、权限、时效、版本等信息 | 各环节保留或变换责任、缺失和冲突时的行为、下游如何使用 | 数据契约引用；行为写入功能/BR/DR/EX。字段、类型、必填性只在 02-contracts/ 定义 |
| TASK | 任务边界与结果策略 | 存在开放输入、信息不足或无法完成的不同结果 | 支持什么任务、完成条件、追问/拒绝/无依据/失败的区分与下一步 | 范围、功能、规则和异常。确定性服务也可适用 |
| OUTPUT | 输出约定与可核对性 | 输出供人工判断或下游系统消费，需要格式或依据约束 | 输出结构、引用与核对方式、不合格结果处置 | 功能与契约引用；结构正确性由功能验收，内容质量由效果验收 |
| MEMORY | 上下文与记忆 | 后续结果依赖历史会话、用户偏好或持久记忆 | 保留内容、主体隔离、有效期、更正/清除、切换范围、冲突与过期处理 | 功能、权限、DR 与异常；不默认要求长期记忆 |
| ACTION | 工具调用与行动权限 | 系统自主选择工具，或代表用户查询、修改、发送、执行 | 授权范围、确认时点、取消、重复执行、部分成功和结果不明时的处理 | 权限、功能、异常与 AC；具体接口引用契约，不指定工具实现 |
| HUMAN | 人工介入与接管 | 存在人工审核、兜底，或失败后必须有人继续处理 | 触发条件、接收角色、交接上下文、接单可见性、无人接手和恢复方式 | 功能、依赖、异常与 AC；不默认建立人工服务团队 |
| LIFE | 数据与知识生命周期 | 持续维护派生数据、知识、索引或版本化产物 | 新增/更新/撤回/过期何时生效、增量/重建是否需要、失败与旧结果如何处理 | 功能、DR、异常；时间和资源限制引用非功能要求 |
| EFFECT | 效果验收与失败代价 | 内容正确性、有用性或任务成功具有概率性，不能仅靠确定性行为判断 | 质量定义、场景代表性、错漏代价、红线、分场景评测、判分与争议处理 | 效果验收引用 03-quality/；数字门槛、基线与波动范围只在验收方案 |
| OPS | 运行观察与变更回退 | 持续上线服务会受模型、策略、知识或数据变更影响 | 观察信号与责任人、复测和处置触发条件、发布与回退行为、回退对已有结果的影响 | 功能/BR/EX 定义行为，效果验收引用效果观测，非功能章引用约束；不默认要求 A/B 平台或热替换 |
| BUDGET | 性能、容量与成本 | 存在在线等待、批处理时限、资源消耗或预算约束 | 计量单位、测量起止点、负载场景、分位数、预算范围、超限处理 | 非功能章引用全局或特殊约束，超限行为写 EX/功能；未知数值写待定或待测 |
| FEEDBACK | 反馈与纠错 | 用户或运营需要报告问题并验证修复 | 反馈入口、关联证据、处理责任、状态回传、修复验证、是否影响后续行为 | 功能、数据契约与异常；不默认将用户反馈直接用于训练或修改知识 |

## 报告与检查

生成正文前，在 `inputs/<需求ID>/generation-report.md` 建立以下表格；生成完成后填实条目引用，审稿修订后同步更新并记录变更原因。手写 PRD 迁移时可创建此报告，仅记录适用性及迁移事实，不声称由独立生成产生。

| 模块 ID | 判定 | 依据或原因 | 正文条目 | 验收条目 | 待确认问题 |
|---|---|---|---|---|---|

- 每个目录模块恰好一行；判定只允许「适用 / 不适用 / 待确认」。领域包可提供检查候选，归入上述模块，不自动新增承诺。
- 「适用」填写本 PRD 已定义的功能、BR/DR/EX、S 等条目与 AC/M 等验收编号。暂缺正文或验收定义时填写 Q-n，空格写 `—`；由 Q-n 解释缺口。只引用外部契约时仍通过本 PRD 条目说明消费责任。
- 「不适用」给出有范围依据的原因，正文、验收和问题列填 `—`。声明不支持某输入也是产品行为，应在 INPUT 中作为适用内容写明。
- 「待确认」必须指向本 PRD 真实 Q-n；问题在确认后回写正文及本表。frozen 不得残留待确认模块或未决的模块问题。
- lint 检查表格完整性、取值及引用是否存在，EFFECT 声明与效果章节是否一致；审稿独立判断触发是否正确、是否漏选和扩写，不能用 lint 通过证明选章正确。

## 三类校准场景

以下均为合成场景，用于检查选章判断，不是客户事实或质量盲测。

| 场景素材 | 应考虑 | 应避免 |
|---|---|---|
| 固定表单资料维护，无模型、无会话、无后台自动执行；字段验证确定，已有性能要求 | INPUT 的字段边界、OUTPUT 的保存结果、BUDGET 的既有约束；通常无需 EFFECT、MEMORY、ACTION | 为普通资料维护生成模型评测、记忆或 Agent 执行章节 |
| 知识从导入到问答，存在不同文档结构、权限与引用，需要更新撤回；是否多轮未说明 | INPUT、META、TASK、OUTPUT、LIFE、EFFECT；MEMORY 待确认；线上使用检查 OPS、BUDGET，反馈与人工能力按证据判断 | 因输入章原在效果章而漏查导入行为；把领域候选形态全部承诺为支持；自动承诺人工接管 |
| 助手调用外部服务执行业务操作，保存会话状态；确认机制与部分失败处理未说明 | ACTION 和 MEMORY 已适用，其具体规则缺口登记 Q-n；TASK、OUTPUT、EFFECT；HUMAN 待确认 | 因权限素材缺失删除 ACTION；凭经验填写执行权限、自动重试、预算或人工团队 |
